# Clue POC：內部社群分析工具改版

可操作的前端 POC。用純 HTML／CSS／JS 撰寫，沒有框架，也沒有任何執行期依賴。全部使用合成資料，**沒有執行真實 AI 分析，也沒有串接任何正式 API**。

## 啟動

```bash
cd Clue-POC/poc && npm start
```

開啟 http://localhost:5173/（要換埠號可設環境變數：`PORT=5174 npm start`）。這個伺服器只綁定 127.0.0.1，請不要用 `file://` 直接開啟，因為瀏覽器會擋 ES module。

## 示範路徑（約 3 分鐘）

1. **社群口碑分析（清單）**：搜尋「AI」、切換狀態篩選、點欄位標題排序，再切到「與我分享」（可用方向鍵切換）。
2. **建立分析**：填寫名稱、客戶與品牌，選「話題分群」→ 資料選「使用示範資料」→ 分群數量改成 5 → 按「開始分析」。
3. **處理中**：約 5 秒後會自動顯示結果。畫面不顯示百分比或剩餘時間。
4. **結果**：專案內頁的四個分頁（話題洞察、分群摘要、關鍵字總表、摘要統整）。
5. **來源查核**：點任一主題進入來源文章列表 → 依平台篩選 → 閱讀全文 → 返回時篩選條件仍保留。
6. **專案管理**：在清單的「⋯」置頂、分享或刪除專案。

## 話題洞察與話題分群：資料來源不同，不互相連結

「話題洞察」是 AI agent 產出的資料，「話題分群」是實際資料跑出的分群結果，兩邊來源不同。因此「話題洞察」分頁內**沒有任何連結**（不連到話題分群，也不連到文章），反向亦然。（POC 目前兩者都以屈臣氏範本資料算出，只是版面上維持分離。）

## DS 依賴與現況（重要）

- **`@dsc-ai-project/ng-ui` 與 `@dsc-ai-project/tokens` 在目前的執行環境安裝失敗**：GitHub Packages 回應 `401 Unauthorized`。`~/.npmrc` 已設定 scope 對應的 registry，但 token 無效、已過期，或尚未通過 SSO 授權。需要的是一組有 `read:packages` 權限、並已對組織完成 SSO 授權的 token（請自行更新 `.npmrc`，不要貼到聊天裡），或一份離線套件 tarball。
- 因此**沒有讀到** manifest、`tokens.json`、theme CSS、`markup.json` 與可攜 CSS。**目前不能宣稱已對齊 Wonder／DS 規範。**
- 暫行做法：使用本機的 Wonder DS tokens（`~/Works/Wonder/wonder-ds`，從 Figma 抽出），複製到 `vendor/wonder-ds/`。App CSS 只引用 `styles/bridge.css` 裡暫定的 `--ds-*` 角色，裡面沒有散寫色碼。拿到套件後只需替換 bridge 這一層。
- **Clue 紫**：`#844b99`。來源是現站 CSS `https://dentsupro.com.tw/clue/assets/index-C9VU5N7i.css` 的 `:root{--C6}`，`.btn--primary` 使用這個值。它與白字的對比為 6.09:1；hover／active 由這個顏色衍生加深。目前只寫在 `styles/theme-clue.css`（`[data-theme="clue"]`）。⚠ 這是從現站樣式讀到的值，不是品牌規範文件，仍待設計系統負責人確認。
