# Raphael Taste Profile — 常駐品味層

生成語言，不是審查規則：`raphael-compact-rubric.md` 回答「對不對」（token 合法、結構合規），這份回答「Raphael 的手感長什麼樣」。動手前讀它定調。

> **數值一律以安裝的 DS tokens 為準。** 本文的具體數字是原始 Raphael 文件的示意值；installed DS 已把這些理念 token 化，有衝突時 DS token 贏。原則層永遠成立，數值層跟著 token 走。

## 1. 一句話人格

**Raphael 是一個做減法的系統主義者：他相信克制會累積成信任，儀式只留給值得慢下來的時刻。**

他對「好看」的定義：使用者第一秒就知道該做什麼，且說不出為什麼覺得舒服。

## 2. 核心美學立場

### 2.1 減法是設計，加法是逃避

**每個元素都要能回答「拿掉它，使用者失去什麼」；答不出來就拿掉。** 資訊靠安排的優先序引導使用者，不靠裝飾、不靠堆疊。

- **好**：一頁只有一個主行動；次要資訊做小、做淡、做遠；覺得畫面空就先問「這頁的任務需要更多東西嗎」。
- **不好**：因為版面「看起來太空」而加插圖、加漸層卡片、加第二個 CTA；每個區塊都想要存在感，結果沒有一個有存在感。

### 2.2 顏色是功能，稀缺造就信任

**一個產品只有一個主色，主色只做一件事：標記行動。** 使用者會學「這個顏色＝在這裡行動」，稀釋它就失去信任。顏色只有三種身分——行動（主色專屬 CTA）、路標（產品色標記你在哪個工具）、語意（綠漲紅跌藍資料）——沒有第四種叫「裝飾」。

- **好**：頁面 90% 是白與灰階；高飽和色一出現就有意義；上升的壞數字由標籤解釋，顏色不說謊。
- **不好**：主色借去做 icon 點綴、標題強調、背景暈染；同畫面三種藍，每種都有 token 名字所以「合法」，但沒有一種在傳達訊息。

### 2.3 節奏來自系統的一致，不是元素的變化

**間距、字級、行高是固定的節拍器；使用者察覺不到它存在，但打破它使用者就會變慢。** 字重只有 Regular / Bold 兩個，層級靠字級×字重的組合，不靠引入更多變化。

- **好**：間距一眼看得出「同組的近、異組的遠」的規律；標題階層是等比階梯，每一階有明確用途。
- **不好**：為了「這裡看起來擠」微調一個 off-scale 值；為了「這個標題要更突出一點點」造一次性字級——每個微調都合理，加總起來整頁節奏散掉。

### 2.4 儀式與工作是兩種 register，切換要果斷

**入口與創建流程有儀式感（漸層、大標、置中、圓形箭頭 CTA）；工作介面純粹是工具（白底、高密度、零裝飾）。兩者反差本身就是 Raphael 的味道。** 建立、決策、開始新事物的時刻值得一點劇場；讀資料、比數字的時刻，任何劇場都是干擾。Hero 是品牌儀式（大字英文標題＋中文副標＋箭頭 CTA，極簡、不放卡片）；Wizard 有固定文法（漸層底上白卡、圓點分頁、灰上一步在左、主色下一步在右）。

- **好**：入口頁捨得留白捨得大，dashboard 捨得密捨得素；從 hero 進工作區像穿過門進入工房——門面有表情，工房裡只有工具。
- **不好**：dashboard 鋪漸層「增加品牌感」；hero 塞快捷卡片「提高效率」；每頁都想兼顧儀式和效率，結果每頁都不倫不類。

### 2.5 輕。層級感用最小的力氣做出來

**陰影統一 10% 黑，只靠模糊半徑和位移分層級；邊框是 1px 的灰；沒有東西沉重地浮著。** 深度用暗示不用宣告。

- **好**：hover 陰影升一階，使用者感覺到回應但說不出哪裡變了；modal 用最重陰影，因為它真的浮在一切之上——重量與語意一致。
- **不好**：彩色陰影、多層 glow、粗邊框強調——用力過猛的層級表達，等於對使用者喊叫。

### 2.6 佈局跟著行為走，按鈕等待使用者

**先問使用者在這頁做什麼、什麼順序做，再決定東西放哪；主行動放在內容之後——自然流程是「閱讀 → 決定 → 行動」。** 每種互動模式有專屬區域（篩選區／資料區／分析區不互相滲透）；內容照使用者工作流程排序，不照資料表結構排。密度是使用頻率的函數——日常重度工具可以密，偶爾查閱的頁面要鬆。

- **好**：閱讀動線和操作動線是同一條線；視線走到底，行動按鈕正好在那裡等他。
- **不好**：CTA 為了顯眼放頁面頂部，逼使用者還沒讀內容就要決定；篩選器和資料操作混在同一排。

### 2.7 資料背後有人，導覽是設計的責任

**展示數字時至少一個元素提醒你數字背後是真實的人；每頁都有向上和橫向的路，方向感由 UI 負責，不外包給瀏覽器返回鍵。**

- **好**：KPI 卡片帶負責人頭像或最後更新者；每頁開場有標題＋一句話說明這裡做什麼。
- **不好**：整頁抽象數字堆疊像機器對機器的報表；點進三層深後只能靠瀏覽器返回。

## 3. 手感細節（signature craft）

看到就知道是 Raphael 的慣用手法，installed DS 有對應 token/元件或屬於合法組合時能用就用：

| 細節 | 做法 | 語意 |
|---|---|---|
| 圓形箭頭 CTA（→） | Hero 與入口的主行動用圓形箭頭按鈕＋下方標籤文字 | 「開始」的品牌儀式，不是普通按鈕 |
| 虛線邊框 | 1px dashed 灰（tag chip、上傳區、可加選項） | 虛線＝邀請（可加入/可選擇），實線＝既定 |
| 中英雙語標題節奏 | 大字英文產品名（ExtraBold）＋一行中文副標 | 入口儀式的固定文法 |
| 內凹式區段切換 | 灰底容器＋inner shadow，active tab 白底浮起 | 橫向導覽，放內容區頂部、不進 shell |
| 漸層公式 | 產品色 → 產品色淡化 20–40%，線性 135° | 漸層從品牌色生長出來，不是外來裝飾色 |
| 極淺表格 | 表頭淡灰底、行間 1px 灰線、hover 微灰 | 資料是主角，容器隱形 |
| 低對比 metadata | 小字級＋淡灰（日期、作者、更新時間） | 存在但不爭取注意力 |
| pill 圓角只給 tag/頭像 | 圓角有詞彙表：小=輸入、中=卡片、大=儀式容器、full=顆粒 | 完整圓角是「可數的小單位」專屬語言 |

## 4. 困難時刻的傾向

- **空狀態**：藏起來，把唯一行動放大——沒有內容就完全隱藏區段，只顯示一顆與 hero 同語言的主行動；不做空狀態插圖、不做佔位卡片。空不是需要安慰的狀態，是需要一個明確出口的狀態（資料為空時畫面仍不能壞，正確呈現常常是收起容器本身）。
- **不可逆操作**：確認步驟的有無由後果決定，不是一律加——低風險操作加確認是不尊重使用者時間，高風險操作缺確認是不尊重使用者資料。破壞性行動永遠紅色＋明確措辭。
- **等待**：誠實（說得出正在做什麼）而克制（穩定節奏，不急促閃爍）；等待不是表演忙碌的機會。
- **錯誤**：講清楚哪裡錯＋給一條明確的路（重試／修改／求助），語氣承認限制而不是系統推責。「發生錯誤，請稍後再試」在這個系統裡不存在。

## 5. Raphael 絕不做的事（anti-patterns）

生成時命中任何一條，當場重做：

1. 主色裝飾性外借——CTA 色出現在非行動元素上。
2. 資料畫面鋪漸層——dashboard／table／analytics 永遠白或近白底。
3. 兩個以上元素搶 primary——兩顆主色按鈕、兩個最大字級標題並存。
4. 任意值——token scale 之外的間距、一次性字級、憑感覺的 hex。
5. 燈箱、懸停依賴、浮動面板——次要內容用行內展開、專屬頁面或底部表單。
6. 空狀態佔位卡片——空的區段畫假卡片或大插圖填版面。
7. 無聲頁面——開場沒有標題＋一句話說明的頁面。
8. 孤島頁面——沒有向上／橫向導覽的頁面。
9. 語意色反轉或挪用——紅綠用於美觀、漲跌顏色說謊。
10. shell 與內容互相滲透——產品色進 shell、shell 深色語言進內容區。
